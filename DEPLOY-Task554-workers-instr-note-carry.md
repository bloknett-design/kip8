# DEPLOY Task 554 — Инструктажи/ПЗ: перенос примечания при автосоздании следующего срока

**Дата:** 2026-11-17 · **Тип: КЛИЕНТ + СЕРВЕР** — `WorkSchedule.gs` **менялся (srvVer 427 → 554)** · Порт из kip8test (байт-в-байт)

## Что изменилось

Заявка: «Внеси дополнение, при отметке галочкой о выполнении и
автоматическом формировании списка на следующий год, примечания так же
должны переноситься. И перенеси всё в kip8.» — продолжение Task 553
(отображение примечаний в блоке «Повторные инструктажи и периодическая
проверка знаний», порт в kip8).

Теперь при отметке **галочки выполнения** записи (Task 418) серверное
**автосоздание записей с новыми сроками** (Task 419 — «список
формируется автоматически» по периодичности «Списка_И_и_ПЗ»; ПЗ 12 мес —
запись следующего года) **переносит примечание** (комментарий, столбец H)
отмеченной записи — в КАЖДУЮ созданную запись:

- новый срок отмеченного пункта (дата + N мес);
- новые сроки детей («в составе» — 9-ОГЭ +3 мес от общего);
- примечание пишется и в лист «Инструктажи» (столбец H), и в ответ
  `created` — карточка работника показывает его сразу (Task 553),
  без перезагрузки;

Границы:

- пустое/пробельное примечание → создаётся запись с пустым
  «комментарий» (trim);
- лимит 500 символов — как `addTraining`;
- **покрытые** записи детей (updated) и **снятие отметки** примечание
  НЕ трогают — меняются только «выполнение»/«просрочен»;
- «Мероприятия» (обучение/прогул/примечание) — без автосоздания,
  как прежде (Task 425).

## Сервер (Apps Script) — ТРЕБУЕТСЯ ДЕПЛОЙ

1. Открыть Apps Script Editor проекта **AKfycbyt…** (где WorkSchedule.gs).
2. Открыть файл **`WorkSchedule.gs`** → выделить всё (Ctrl+A) → вставить
   содержимое `scripts/WorkSchedule.gs` репозитория kip8 (изменения:
   `setTrainingDone`/`_autoCreateNextTrainings`/`_appendTrainingRow` —
   Task 554; остальное — байт-в-байт прежнее).
3. **Deploy → Manage deployments → Edit → New version → Deploy**.
4. Проверка: отметить галочкой выполнение инструктажа с примечанием →
   в тосте «новые сроки: …» (без «старой версии»), в карточке созданные
   записи — с тем же примечанием; `srvVer: '554'` в ответе
   (`workSchedule.setTrainingDone`).

Без серверного деплоя клиент работает как прежде (примечание НЕ
переносится) и **предупреждает**: тост «Сервер Apps Script старой
версии — замените WorkSchedule.gs и создайте новую версию развёртывания»
при каждой отметке выполнения (порог предупреждения поднят с 427 на 554).
