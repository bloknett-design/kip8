## Диагноз

`Flowmeter.gs → updateReading` писал meters-строку БЕЗ замка и только ПОТОМ вызывал
`appendToArchive` под `Utils.withLock` (`tryLock 10 c`). Замок скрипта Apps Script —
один на все выполнения: при вводе всех 12 расходомеров подряд или параллельных
beacon-доставках при закрытии приложения очередь на замок длинная, и ПОСЛЕДНИЙ в
очереди (№12) упирался в таймаут → `server_busy` → ошибка **глоталась как
«non-critical»** → `ok:true` → строка архива терялась при записанном meters.
Клиент удалял запись из outbox — повторной доставки не было. Усилитель: day-дедуп
`_flushOutbox` сверялся только с `flowmeter.list` (meters) — совпадение meters без
строки архива навсегда вычищало запись из outbox.
