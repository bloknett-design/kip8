**Что переносится** (из `kip8test@372530a` в боевой `kip8`, один инкремент
SW `kipia-v408` → `kipia-v409`):

1. **Ввод показаний «за месяц»** (Task 286) — в карточке «Расходомеры
   хозрасчётные / Хозрасчёт №1» переключатель **За сутки / За месяц**
   (недельная форма удалена — Task 289). Значение = расход за период,
   запись **только в архив** (`hozraschet_archive`, колонка R
   `entryType`): meters-строка не меняется, «Последние показания»
   остаются суточными. В хронологии — бейдж «мес» + диапазон дат;
   график строится только по суточным записям.

2. **Дни периода считаются ВКЛЮЧИТЕЛЬНО** (Task 289) — 01.08–31.08.2026
   = **31 полный день** (не 30).

3. **Блок «Передано показаний (контроль)» удалён** (Task 288) — вместе
   с логикой счёта.

4. **Счётчик «За неделю»** (Tasks 289-291) — отдельной строкой ПОД
   заголовком «Хронология показаний» (только Хозрасчёт №1):
   - последняя **ПОЛНАЯ** календарная неделя (пн–вс, закрывшаяся в
     прошлое воскресенье);
   - **сумма показаний, переданных за КАЖДЫЕ сутки недели** (т + Гкал
     по тому же принципу);
   - период подписан: «За неделю 24.08–30.08.2026: 345,60 т · 1,260 Гкал»;
   - в начале каждой недели автоматический переход на новую закрывшуюся
     неделю **без записи в архив**;
   - перенос текста после двоеточия (если строка не влезает в экран);
   - строки заголовка и счётчика — непрозрачный фон.

5. **Заголовок графика** (Task 292): «Показания, т» → **«Показания
   (посуточно), т»** — уточнение, что график строится только по суточным
   записям. Для остальных хозрасчётов — «Расход, <ед.>», как прежде.

Серверная логика за сутки — **не тронута** (прежний маршрут
`flowmeter.updateReading`, meters-строка, тосты).

## Шаги деплоя

### 1. Обновить Apps Script (сервер) — 3 файла

В проекте Apps Script (тот же, где развёртывание `AKfycbyt…/exec`)
замените содержимое файлов:

| # | Файл в Apps Script | Откуда взять (справочные копии в репо) |
|---|--------------------|------------------------------------------|
| 1 | `Flowmeter.gs` | `scripts/Flowmeter.gs` |
| 2 | `FlowmeterArchive.gs` | `scripts/FlowmeterArchive.gs` |
| 3 | `Code.gs` | `scripts/Code.gs` (добавлен один case — см. ниже) |

⚠️ **Code.gs — единственное изменение**: добавлен маршрут

```javascript
case 'flowmeter.updatePeriodReading':
  return _json(Flowmeter.updateReading(payload));
```

(вставлен перед секцией «График работы персонала»).
Если вам проще — вставьте только этот блок вручную в существующий
Code.gs, остальное в Code.gs не менялось.

Зачем отдельный маршрут: если фронтенд уже обновлён, а сервер ещё нет,
ввод «за месяц» вернёт **«Unknown action»** и ничего не запишет (иначе
агрегат записался бы как суточные показания и испортил бы meters-строку).
Это защита, а не ошибка.

### 2. «Новая версия» развёртывания (URL НЕ меняется!)

⚠️ **ВАЖНО (урок Task 284):** «Управление развертываниями → …» —
**«Новая версия»** у СУЩЕСТВУЮЩЕГО развёртывания `AKfycbyt…/exec`.
**НЕ создавайте «Новое развёртывание»** — у него будет другой URL, и
приложение снова пойдёт мимо.

### 3. Заголовок архива R1 — самовосстанавливается

Колонка R (`entryType`) в `hozraschet_archive` добавится сама: при
первой записи «за месяц» заголовок R1 проставится автоматически
(self-heal). Если хочется сразу — можно один раз выполнить
`flowmeterInitArchive()` (не обязательно).

### 4. Фронтенд — Ctrl+Shift+R ×2

Откройте боевое приложение `https://bloknett-design.github.io/kip8/` и
дважды нажмите **Ctrl+Shift+R** (или в PWA закрыть/открыть после
обновления) — Service Worker обновится `kipia-v408` → `kipia-v409`.
